# Requirements for running neuro-san as a LIBRARY under Pyodide.
#
# Scope: AsyncDirectAgentSession only -- DirectAgentSessionFactory.create_async_session(),
# a SHARED_LOOP executor pool, and the "openai-wire" chat model. No server, no CLI,
# no provider SDKs. See neuro_san/internals/run_context/langchain/llms/wire/
# openai_wire_chat_model.md.
#
# HOW THIS WAS DERIVED
#
#   Measured, not guessed, in two passes.
#
#   1. A full agent run (multi-agent tool calls against a real OpenAI-compatible
#      server) was traced for every module it imported, and those modules mapped back
#      to distributions. 98 distributions were imported; 28 came only from this
#      developer's environment (requirements-build.txt: the optional provider packages
#      and their google/grpc/opentelemetry trees). That left 70 from requirements.txt.
#
#   2. This file was then installed into a clean venv and the library actually run,
#      which is what turned the drop list from hypothesis into fact. Two packages had
#      to be added back -- aiofiles and aiohttp, both module-scope imports on the
#      library path (see below). Nothing else was missing, and every drop below was
#      confirmed absent from the working environment.
#
#   VERIFIED on 2026-10-08: clean venv (Python 3.12.9) + this file + leaf-common,
#   running neuro_san.client.shared_loop_agent_cli against the bundled mock LLM
#   server (tests/mock_llm_server) with threads made unavailable, SHARED_LOOP
#   executor pools and a serial manifest read. Full request/response round trip,
#   clean session close.
#
# WHAT IS STILL NOT PROVEN: that this runs under Pyodide itself. The native-code
# section at the bottom now has measured answers rather than open questions, but
# nothing here has been executed in a browser.

# -- HTTP -------------------------------------------------------------------
# Required by neuro-san CORE, not just by AiohttpChatTransport. Three library-path
# modules import it at module scope, each only for exception types:
#   internals/graph/activations/branch_activation.py:23    ClientConnectionError
#   internals/graph/activations/external_activation.py:29  ClientPayloadError
#   internals/run_context/utils/activation_capsule.py:23   ClientConnectionError
# So selecting transport: "pyodide" does not drop aiohttp today. Two separate
# changes would be needed: make those three imports lazy or provider-neutral, and
# make openai_wire_llm_policy.py stop importing both transports at module scope.
# Pyodide does ship aiohttp, so this is a cleanup, not a blocker.
# Same reasoning: Pyodide 314.0.7 ships aiohttp 3.13.5. Allowing 3.14 pulls a yarl
# newer than the 1.23.0 Pyodide has, and neither has a pure-Python wheel to fall
# back on, so the install fails outright.
aiohttp>=3.13.0,<3.14

# -- MCP tools --------------------------------------------------------------

#   mcp/langchain_mcp_adapter.py:30 -> langchain_mcp_adapters.client

# DirectAgentSessionFactory then fails outright.
langchain-mcp-adapters>=0.1.7,<0.2.0

# Pinned exactly, not ranged. langchain-mcp-adapters asks for "mcp>=1.9.2" with no upper
# bound, and micropip's resolver followed that rather than intersecting it with a range
# here -- landing on mcp 2.x, which renamed McpError to MCPError and breaks the adapter:
#   ImportError: cannot import name 'McpError' from 'mcp.shared.exceptions'
# pip intersects correctly, so this only bites under micropip. An exact pin removes the
# ambiguity; also name it explicitly in the micropip.install([...]) list to be certain.
mcp==1.30.0

# ===========================================================================
# NATIVE CODE -- measured against Pyodide's package index
# ===========================================================================
#
# The verified closure is 72 distributions, of which 18 ship compiled extensions.
# Checked against pyodide-lock.json for Pyodide 0.28.3 (which is Python 3.13.2):
#
#   SHIPPED BY PYODIDE (15) -- no build needed:
#       aiohttp   cffi      charset-normalizer  cryptography  frozenlist
#       multidict orjson    propcache           pydantic-core pyyaml
#       rpds-py   wrapt     xxhash              yarl          zstandard
#
#   NOT IN PYODIDE (3), each confirmed genuinely required by uninstalling it and
#   re-running until the import failed:
#       websockets   langgraph_sdk/stream/transport/sync_ws.py
#                    NOT a problem: websockets publishes a pure-Python
#                    py3-none-any wheel, so micropip can install it as-is.
#                    Its C speedups extension is optional.
#       uuid-utils   langchain_core/callbacks/manager.py
#                    Rust, no pure-Python fallback. Needs an emscripten build.
#       ormsgpack    langgraph/checkpoint/serde/jsonplus.py:30
#                    Rust, no pure-Python fallback. Already hand-built:
#                    neuro-san-wasm-build/wheelhouse holds
#                    ormsgpack-1.12.2-cp314-cp314-pyemscripten_2026_0_wasm32.whl.
#
# So the build burden is ONE package: uuid-utils. ormsgpack is done.
#
# VERSION GAP -- the part that actually needs a decision.
#
# Every native Pyodide bundles is older than what this closure resolves to today,
# and four of those gaps violate a hard constraint rather than merely lagging:
#
#       package         pyodide 0.28.3    required by
#       orjson          3.10.16           langgraph-sdk needs >=3.11.5
#       pydantic-core   2.27.2            pydantic 2.14 pins ==2.50.0
#       rpds-py         0.23.1            jsonschema needs >=0.25.0
#       aiohttp         3.11.13           neuro-san's own pin, >=3.13.0 (ours to relax)
#
# (cffi and yarl also look too old, but only as a consequence of the newer
# cryptography and aiohttp above them; against Pyodide's own versions of those two
# they are fine.)
#
# Two ways out, and they are not equivalent:
#   1. Target a newer Pyodide. The hand-built ormsgpack wheel above is cp314, so the
#      build already assumes a Pyodide newer than public 0.28.x, which will ship
#      newer natives. Re-run this comparison against the Pyodide actually being
#      targeted before building anything -- these numbers are for 0.28.3 and are
#      probably pessimistic.
#   2. Pin the Python side down to what Pyodide bundles. Attempted here and pip
#      returned "resolution-too-deep", so it is not a one-line change; it would mean
#      older pydantic, jsonschema and langgraph, which may not satisfy langchain 1.x.
#
# Option 1 is the one to try first.
